# FHM-100 最终选股架构（锁定版）

**状态：最终业务流程基线。** 后续开发、数据接入、测试和运行报告均以本文的六阶段流程为准。若要改变顶层流程，必须先有明确的实盘问题或验证证据，不再反复重构方向。

## 一、唯一顶层流程

```text
全球新闻 / 国内政策 / 行业事件
            |
            v
事件识别 + 预期差 + Price In 程度
            |
            v
行业主线 + 资金持续集中 + 龙头强度
            |
            v
全市场初筛 + 动态个股数据补充
            |
            v
M2 / M3 / M5 / M8 决策门 + 真实15分钟买点确认
            |
            v
可执行股票名单、入场区间、止损参考、失效条件
```

这是模型对外唯一的选股主流程。M1数据管理、M4因子计算是底层支撑；不作为额外的用户决策阶段。M6/M7/M9中的预测、执行和验证能力，只在能够提供真实、可审计的数据与结果时作为内部支撑，不得擅自增加新的前置流程或绕过上述决策门。

## 二、六阶段输入、判断与输出

### 1. 全球新闻、国内政策、行业事件

每次模型运行时收集可获得的：
- 全球宏观、利率、汇率、地缘政治、海外科技、能源及贸易政策事件；
- 国内政策、监管、产业规划、重要会议和正式文件；
- 行业供需、价格、技术、订单、产品发布及产业链事件；
- 上市公司公告及其他可核验公司级事件。

每个事件尽可能保留原文/来源、标题、事件类别、涉及行业与证券、首次发现时间 `first_seen_at`、来源发布时间 `published_at`、模型实际可用时间 `available_time`、去重键和证据链接。来源时间缺失或冲突时标记不确定，不自行补造时间。

新闻和政策只建立事件上下文，不因关键词、情绪词或“利好”标签直接提高个股正式分数。

### 2. 事件识别 + 预期差 + Price In程度

先识别事件事实和可信度，再判断市场预期与价格反应。事件状态统一采用：

- `UNPRICED`：有可信事件，但尚无足够价格反应证据；
- `PRICING_IN`：价格、成交或行业扩散正在反映事件；
- `PARTIALLY_PRICED`：已有明显反应，但仍有可验证预期差；
- `FULLY_PRICED`：主要预期已被快速或充分反映，追涨性价比下降；
- `POST_EVENT_FADE`：事件兑现后价格/资金反应衰减或转弱；
- `UNKNOWN`：时间、行情、映射或证据不足。

判断至少考虑：
- 事件发生/首次可用前的个股与行业5/20日表现；
- 首次可用后的首个可交易窗口、1/3/5交易日行业超额表现；
- 开盘缺口、成交额/换手异常、行业上涨扩散；
- 龙头与跟随股强弱差、冲高回落、量价背离；
- 后续增量信息及事件可信度。

事件发生日的日线收盘价不得在事件盘中首次可用时被当作“事件前”收益。非交易时段消息从下一个可交易窗口开始观察。任何历史回放必须按当时真实可用时间截断，不能将今天抓取的新闻或行情倒灌为历史已知信息。

同一催化引发的新闻、行业上涨和个股上涨属于相关证据，必须去重/关联，不能重复加分。Price In结果用于判断预期差、主线研究优先级和追涨风险；它不是独立买入信号。

### 3. 行业主线 + 资金持续集中 + 龙头强度

主线判断同时要求事件逻辑和市场行为相互印证，重点观察：
- 行业阶段：启动、确认、扩散、高潮、分化、退潮；
- 行业相对市场强度、上涨家数和联动广度；
- 资金是否连续向该行业/主题集中，而非单日成交额突然放大；
- 行业成交额/换手占比的连续变化、持续性和相对市场变化；
- 龙头的相对强度、领涨持续性、成交质量、回撤承接；
- 龙头与跟随股的梯队、分化和补涨扩散；
- 高位滞涨、放量不涨、冲高回落、资金撤离等退潮信号。

资金流字段必须注明供应商口径和可用性。只有成交额时，只能称成交活跃度或资金关注代理，不得冒称真实净流入。行业主线评分不得由新闻数量或单日涨幅单独决定。

### 4. 全市场初筛 + 动态个股数据补充

先扫描全市场当前可用行情与基础状态，再结合M2基础约束、行业主线、资金持续性、龙头强度、个股相对表现和Price In风险形成研究池。

个股历史数据获取采用动态分层，不将80只设为永久策略上限：
1. 全市场实时快照和基础过滤；
2. 主线内领涨、强势、补涨、回撤承接等多类型候选初筛；
3. 对排名靠前且缺少关键数据的候选优先补充日线、公司行为、行业映射等数据；
4. 对接近买点的股票优先补充真实15分钟数据；
5. 按API额度、运行时长和实际数据成功率控制批次；达到运行预算后停止扩展，保留已完成结果；
6. 缺数据的个股标记具体缺项并降级/跳过，不伪造数据、不用其他股票数据填补，也不阻塞全市场扫描。

动态补充优先级由研究机会、主线归属、资金持续性、龙头/补涨角色、接近买点程度和数据缺口共同决定，不能只按当日涨幅排序。前瞻抓取的历史行情仍是retrieval-time数据，不能自动获得历史PIT资格。

### 5. M2 / M3 / M5 / M8 + 15分钟买点确认

所有正式交易候选必须通过以下决策门：

- **M2 股票池过滤**：交易状态、上市/风险状态、流动性、重大风险和基础数据质量等硬过滤。被M2排除的股票不能由高分重新放行。
- **M3 市场状态**：判断风险偏好、市场广度、情绪周期和当前适用策略；风险状态不允许新开仓时，停止正式买入授权。
- **M5 策略判断**：按已定义的A/B/C策略分别评估趋势延续、事件交易、强势股回撤反转。各策略独立评分，必须具备完整合格因子与硬门槛；缺失因子不得填零、均值或代理值，不得用总分抵消硬门槛失败。
- **M8 组合风险**：必须具备有效风险上下文，检查组合风险预算、行业/个股集中度、仓位和止损风险。风险上下文未配置或不可用时保持关闭，不猜测账户资金、持仓或风险偏好。
- **15分钟买点确认**：使用真实、带交易时间戳的15分钟行情，确认突破/回踩/承接、成交质量及买入区间；检查追高、跳空、流动性和买点失效。缺少真实15分钟数据、非交易时段或数据过期时，不给出已确认买点。

15分钟确认是最后一道时点确认，不得单独授权交易，也不能绕过M2/M3/M5/M8。任何门槛阻断时，结果只能进入观察/待补数据名单，不得混入可执行名单。

### 6. 最终输出

每次运行分开输出“可执行名单”和“观察/待补数据名单”。只有所有正式门槛通过的股票才能进入可执行名单。

每只可执行股票至少输出：
- 股票代码、名称、所属主线/行业、策略类型（A/B/C）；
- 事件依据、预期差判断、Price In状态及置信度；
- 行业资金持续集中证据、龙头/补涨角色；
- M2/M3/M5/M8各门结果和数据时间；
- 15分钟确认状态及确认时间；
- **入场区间**及触发条件；
- **止损参考**、风险预算/仓位约束；
- **失效条件**（如主线退潮、资金转弱、关键价格结构破坏、事件证伪、买点超时或风险门变化）；
- 数据缺口、来源与可信度说明。

如果没有股票通过全部门槛，明确输出“当前无可执行标的”，可以附研究观察名单；不得为了凑数降低门槛。

## 三、不可变更的安全与数据原则

1. 新闻不是买入信号；Price In不是买入信号；行业主线不是个股买点。
2. 任何分数都不能覆盖M2/M3/M5/M8硬门槛。
3. 所有数据按真实可用时间处理；历史回测必须满足PIT和公司行为口径。
4. 前瞻数据、当前行业成分快照、供应商代理资金流不得冒充历史PIT真值。
5. 不生成虚构行情、15分钟K线、账户风险参数、入场价或止损价。
6. 研究候选、数据就绪候选、正式可执行候选必须分层展示，禁止混称。
7. 运行预算只限制数据补充批次，不改变选股逻辑；预算不足时优先级排序并明确降级。

## 四、开发验收顺序

开发以打通真实运行闭环为目标，不为追求庞大历史数据而无限拖延：
1. 确认事件采集、时间字段、去重、行业映射和Price In观察链路；
2. 确认行业阶段、资金持续集中和龙头强度能在每次扫描中产生可审计结果；
3. 完成全市场初筛及动态个股数据补充，并记录候选覆盖率/成功率/耗时；
4. 将M2/M3/M5/M8门接入主运行路径，保留fail-closed；
5. 接入真实15分钟行情与买点确认；
6. 输出上述可执行名单字段；没有通过门槛时只输出观察名单；
7. 用有限、代表性的历史样本做关键逻辑验证，避免以无PIT数据冒充历史回测。

每次运行至少审计：全市场扫描数、研究候选数、动态补数选择/成功/失败数、事件与Price In覆盖、行业资金/龙头证据覆盖、各门阻断原因、15分钟有效覆盖、正式可执行数量及运行耗时。
