# 全市场扫描与分层历史数据策略

## 目标

日常运行不再对当前上市的约 5,500 只股票逐只下载多年历史。系统分成两层：

1. **全市场实时行情层**：获取当日沪市、深市、科创板、北交所有效报价，完整保存为 `output/market_snapshot.csv`。它用于全市场观察与候选发现，不依赖多年历史回填。
2. **深度历史层**：按当日成交额从全市场快照选取最多 600 只股票，再逐只获取近 160 个自然日的日线，供当前技术结构观察使用。

## 当前实现边界

- 当前实时行情接口返回多少只有效股票，就记录多少只；不再在获取股票池阶段截断到 350 只。
- 不再排除科创板和北交所代码段；ST、退市名称以及无效报价仍不进入当日候选观察。
- 深度历史池上限为 600，按成交额降序；同额时按证券代码稳定排序。
- 每次运行保存完整市场快照 CSV、深度历史扫描结果、逐只数据错误及运行状态。
- 5,580 只证券的多年历史回填仍保持手动触发，不作为日常扫描的前置条件。
- 动态候选若不在前 600 深度池中，后续可另行按候选触发补数；本次改动先建立全市场快照与有界深度扫描的基础链路。

## 重要限制

- 全市场实时快照不等于全市场历史行情。
- 深度池按成交额排序，不等于 FHM-100 正式策略评分，也不能替代策略硬门槛。
- 当前抓取的历史 K 线只有检索时间，没有历史首次公开可用时间；所有此类数据仍为 `historical_pit_eligible=false`。
- 本改动不会生成正式 A/B/C 买入信号，也不会改变 80 分门槛或填补缺失因子。
- 正式历史回测仍需退市股票、历史股票池、公司行为和 PIT 数据准入。

## 验收

- 单元测试覆盖：全市场股票保留、600 只上限、成交额排序、科创板/北交所不被代码过滤、代码格式归一化及无效报价剔除。
- 合并后以 GitHub Actions 运行完整回归测试；下一次日常扫描报告必须分别显示全市场快照数量和深度历史扫描数量。
