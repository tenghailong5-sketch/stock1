# FHM-100 M4 数据源映射与准入清单

> 状态：工程审计基线（2026-11-11）。本文件区分“接口可能返回字段”和“可用于历史点时研究的数据”。只有同时具备来源、字段定义、交易日、可用时间、版本/修订信息及历史覆盖验证的数据，才可进入正式 M4/M5。当前每日扫描器仍是技术观察工具。

## 1. 已核实的现有实现

- `src/fhm100.py` 当前调用 `ak.stock_zh_a_spot_em()` 获取当下 A 股快照，并调用 `ak.stock_zh_a_hist()` 获取个股日线；快照按成交额排序后最多保留 350 只。
- 当前扫描器已调用 `src/model/m4_factors.py::price_structure()` 计算可用的当日 K 线结构、成交额/量比等观察原语；历史跨日总收益字段仍因缺少经验证的 PIT 公司行为序列而留空。扫描器没有把这些观察原语升级为 M5 正式因子，也没有接入完整 M5 评分。
- 现有日线请求使用 `adjust=""` 原始价格。仓库没有接入完整点时公司行为账本，故除权除息附近的跨日收益、均线及回测标签不具备正式总收益口径。
- AkShare 返回一份历史数据，并不自动证明历史时点当时可见的版本。若没有供应商发布时间/修订记录，不能把今天下载的历史数据回填成历史决策时已知数据。

## 2. 因子—数据映射矩阵

| M4 因子/输入 | 模型所需原始字段 | 当前代码/可用接口线索 | 点时与历史覆盖结论 | 当前准入 |
|---|---|---|---|---|
| 行业相对强度（A/C） | 个股当日历史行业代码；行业指数 5/20 日收益；市场 5/20 日收益；available_time | M4 原语已实现计算；扫描器没有历史行业映射或行业指数接入 | 当前行业成分快照不能代表历史成分；行业指数历史行情也需保存发布时间、分类版本及成分口径 | **BLOCKED** |
| 个股残差强度（A） | 个股/市场/所属历史行业同步日收益；历史行业代码；滚动窗口 | M4 原语已有 PIT 过滤和过去窗口 OLS | 依赖上一项历史行业归属；还需冻结收益口径、Beta 窗口、截距处理及停牌缺失规则 | **BLOCKED** |
| 价格结构（A/C） | OHLC、交易日、成交量/额、可用时间；复权/公司行为信息 | `ak.stock_zh_a_hist()`；`price_structure()` | 日线字段可作为当前观察输入；现有扫描使用未复权数据，且供应商历史修订可见时间未留档 | **OBSERVE_ONLY** |
| 成交质量（A/B/C） | 成交额/量、5/20 日均值、换手率、量价关系、可用时间 | 现有日线有成交额/量；M4 原语计算均值比、放量滞涨、缩量回撤 | 换手率未接入；成交额/量无法替代换手率；历史可用时间/修订快照缺失 | **PARTIAL** |
| 市场环境（M3/A/C） | 指数 OHLC/均线、全市场上涨比例、涨跌停数量、成交额、波动率；历史股票池 | `market_state.py` 有计算器；现有扫描器没有接入这些全市场历史序列 | 当前股票快照/当前成分不能重建当时市场广度；需包含后来退市股票的历史股票池 | **BLOCKED** |
| 资金流 | 3/5 日净流入、连续性、行业相对流、主动买卖/大单口径 | 当前扫描器未调用资金流接口；模型将其列为待验证模块 | 不同供应商“大单/主力”口径不统一；必须先做供应商一致性和控制价格/成交额后的增量检验 | **UNAVAILABLE** |
| 消息催化/风险 | 原始公告/新闻、来源、发布时间、实际发生时间、分类、去重/修订 | 当前只有可选 AI 对报告文字点评，不是新闻事件数据管线 | AI 点评不能充当事件源或打分输入；必须保留原文来源和首次可用时间 | **UNAVAILABLE** |
| 涨跌停事件（B） | 当日适用涨跌停价、盘中触及、收盘封板、开板/回封、时间序列 | 当前无逐笔/分钟级事件管线 | 日线 OHLC 最多辅助判断价格边界，不能还原开板次数、封单、排队或触板后回落路径 | **UNAVAILABLE** |
| 次日价格行为（B） | 次日开盘及盘中成交/价格确认 | M5 明确只允许 `stage="next_day"` | 必须在次日真实数据可用后独立计算；不得回填到前一日收盘评分 | **NEXT_DAY_ONLY** |
| 过热/行业偏离 | 个股相对行业偏离、横截面排名、催化状态 | M4 有基础价格与排名原语，缺少完整输入映射 | 不得用全市场混合排名代替行业/策略定义的同类横截面 | **PARTIAL** |

准入状态含义：
- `READY`：字段、口径、点时、覆盖及质量检查均通过。
- `OBSERVE_ONLY`：可用于当日观察，不可用于历史正式评分/回测。
- `PARTIAL`：仅部分字段可计算，整组加权因子仍视为缺失。
- `BLOCKED`：缺少关键历史映射或点时数据。
- `UNAVAILABLE`：当前工程没有接入合格来源。
- `NEXT_DAY_ONLY`：只允许在次日数据真实可用后计算。

## 3. 数据源接入规则

1. 每条记录至少携带 `symbol/industry_code`、`trade_date`、`available_time`（带时区）、`source_id`、`source_revision`；公告另需 `publish_time` 与 `event_time`。
2. `available_time` 必须是该数据实际可被策略系统获取的时间，不得简单把历史交易日收盘时间写成可用时间。
3. 行业分类必须是带 `valid_from/valid_to` 的历史成员表，并记录该版本首次可用时间；不能用今天的行业成分回填过去。
4. 股票池、指数广度和涨跌停统计必须使用当时可交易/上市的全量证券集合；不能只用今天仍上市的股票。
5. 复权/总收益数据必须来自可核验公司行为账本。遇到配股、复杂分红、拆并股或无法核验的行为，相关区间应拒绝进入收益标签，而不是猜测调整因子。
6. 横截面排名必须按同一决策时点、同一策略定义的比较集合计算；缺失值保持缺失，不以 0、均值或其他股票的值补齐。
7. 每次运行应保存原始输入快照哈希、数据源版本、抓取时间、代码提交 SHA 和决策时点，保证报告可复现。

## 4. 当前禁止事项

- 不把实时快照中的行业字段当成历史行业成员。
- 不把今天抓取的历史 K 线假定为历史当时可见的原始版本。
- 不用成交额/量比替代换手率、资金流、订单流或盘口事件。
- 不用日线 OHLC 推测开板次数、封单强弱或盘中触板路径。
- 不让 AI 文本点评生成因子分数、催化事件或收益概率。
- 不因候选不足而降低 80 分门槛、填补缺失因子或缩小硬门槛。
- 在完整输入接通前，不将 M4 原语或 M5 接口接入正式买入信号。

## 4A. 涨跌停池情绪观察指标（不进入评分）

`src/model/market_sentiment.py` 只从五类供应商池快照汇总可直接观察的数量：涨停池、跌停池、炸板池、昨日涨停池、强势股池，并统计涨停池中可解析的“连板数”最高值及字段覆盖数量。

- 不计算炸板率/封板率：当前池接口语义、集合是否互斥及时间边界尚未通过真实接口验证。
- 不将“炸板次数”字段的总和误当作炸板股票数或完整盘中开板事件。
- 不把昨日涨停池当作当日涨停池。
- 输出标记为 `historical_pit_eligible=false`、`scoring_eligible=false`，仅供人工观察和前瞻积累。
- 缺少任一必需池、重复池、记录数与声明数量不一致时，整组汇总 fail closed。

## 5. 下一步验收顺序

1. 固定 AkShare 版本与每个接口的字段/单位/复权口径，加入 schema contract tests。
2. 验证日线供应商可用时间与历史修订能力；若无法获得历史可用时间，明确限定为前瞻运行，禁止用其做历史 PIT 回测。
3. 建立可版本化历史行业成员和行业指数数据；通过历史日期抽样核对成分变化。
4. 建立市场指数、历史全市场股票池、广度和涨跌停统计；验证退市证券未被幸存者偏差剔除。
5. 完成公司行为账本与总收益序列测试。
6. 之后再接换手率、资金流、公告事件及分钟级涨跌停事件。
7. 所有数据契约通过后，才允许 M4 输出完整因子包并交给 M5；随后进行滚动样本外回测和交易成本/涨跌停不可成交模拟。

**当前结论：** 现有免费 AkShare 接口足以支撑一部分日常技术观察，但现有仓库没有证据证明它能单独提供完整、可回放的 FHM-100 M4 点时数据集。不能因此宣称 M4 已完成，也不能输出正式 A/B/C 交易信号。

## 6. AKShare 接口核验与前瞻采集适配器

依据 AKShare 公开接口文档，当前可确认以下接口形态：
- `stock_zh_a_hist` 提供日线 OHLC、成交量、成交额及换手率字段；但接口返回历史行本身不包含逐行原始发布时间/修订历史。
- `stock_board_industry_name_em` 可获取当前行业列表，`stock_board_industry_cons_em(symbol=...)` 可获取指定行业当前成分股；这不是带生效区间的历史成分接口。
- `index_zh_a_hist` 可获取指数历史日线，但指数行情本身不能替代全市场历史股票池、上涨比例和涨跌停数量。

因此新增 `src/providers/akshare_pit.py`：
- 历史日线统一以**本次实际抓取时间**作为 `available_time`，并标记 `historical_pit_eligible=False`。不能把历史交易日期伪装成当时可用时间。
- 当前行业成分采集只保存 `observed_at` 快照，不制造 `valid_from/valid_to`。只有从系统开始持续留档的未来快照，才可能支持采集起始日之后的成员观察；不能回填采集起始日前的历史行业成员。
- 每次结果附带来源标识与内容 SHA-256 revision，便于识别重复/变化快照。该哈希不是供应商原始版本号，也不代表供应商修订完整性。
- 新增离线契约测试，不在 CI 中调用外部行情接口，避免网络波动造成不稳定测试。

**重要限制：** 这些适配器是前瞻数据留档的起点，不是完整历史 PIT 数据源，也没有接入生产扫描器。全市场广度、涨跌停历史、公司行为验证及事件数据仍需单独完成。

参考：AKShare 官方指数接口文档与其 A 股接口字段说明；行业列表/成分股接口说明见 AKShare 接口参考。 


### 前瞻采集归档（2026-11-11）
新增 `src/collectors/forward_archive.py` 与 `.github/workflows/forward-archive.yml`：
- 每个采集批次保存上证综指、深证成指、创业板指、科创50、沪深300的历史日线响应；逐行内容哈希用于去重，所有行仍标记为 retrieval-time-only，不能用于历史 PIT 回测。
- 每个交易日保存当前行业成分快照；只记录观察时间，不生成历史有效区间。
- 每次采集同时调用 `stock_zh_a_spot_em`，归档当前快照的上涨家数、下跌家数、平盘家数、有效报价数、缺失报价数和覆盖率。
- 市场广度数据只表示该次供应商快照，不能证明是交易所官方收盘统计，也不能还原历史全市场可交易股票池；不从日涨跌幅推断涨停/跌停事件。
- JSONL 归档采用追加去重与原子替换；遇到空响应、字段缺失或已有档案损坏时拒绝写入对应批次。

该工作流使用工作日 16:30（北京时间）定时触发，但 GitHub schedule 只会在默认分支运行。合并到默认分支并确认 Actions 有写入权限之前，自动采集不会启动。采集程序目前只完成离线模拟测试，尚未执行真实行情接口验证。


### 涨停/跌停池前瞻快照
新增 `src/providers/akshare_limit_pools.py`，按交易日参数（`YYYYMMDD`）调用以下四类接口：
- `stock_zt_pool_em`：涨停股池；
- `stock_zt_pool_dtgc_em`：跌停股池；
- `stock_zt_pool_zbgc_em`：炸板股池；
- `stock_zt_pool_previous_em`：昨日涨停股池；\n- `stock_zt_pool_strong_em`：强势股池，用于观察连板梯队与强势股结构。

每类接口单独形成一条日期快照，保留供应商原始字段列表、记录数量、采集时间、来源、内容哈希和 `historical_pit_eligible=false` 标记。空池只有在响应仍包含预期代码列时才记录为零条；空响应、字段缺失、重复证券代码、无效日期或接口不可用均 fail closed。四类数据全部获取和校验后才会写入归档。

**事件语义边界：** 这些是供应商按日返回的股票池，不是逐笔/逐秒交易所事件流。炸板池不等同于完整盘中开板次数事件账本；昨日涨停池是次日观察列表，不可作为当天涨停集合。不能从日线涨跌幅推断涨停/跌停，也不能将接口返回的历史日期记录伪装成当时已采集的 PIT 数据。历史可查询范围与接口可用性应以实际运行时响应为准；当前实现只按采集日向前留档，不做历史批量回填。

当前新增适配器与归档测试均为离线 fake-provider 契约测试，尚未在 GitHub Actions 中访问真实东方财富接口；正式采集启动前仍需进行一次人工触发的真实接口 smoke test，并核验四个端点返回字段与空池语义。

### M4 扫描器行级来源链路修复（2026-11-12）
`history()` 现在将 `normalize_daily_history_snapshot()` 生成的逐行 `available_time`、`source_id` 和 `source_revision` 合并回扫描用日线，并在进入 `price_structure()` 前完整保留这些字段。M4 的决策截止时间独立于每行实际抓取时间，不再用一个当前时间戳覆盖所有历史行的来源元数据。该修复解决了扫描器调用 M4 时缺少必需 lineage 字段而逐只股票失败的问题。

**准入边界不变：** 行情历史行的 `available_time` 是本次抓取时间，不是原始历史发布日期；因此它们只支持当前扫描的 retrieval-time observation，不具备历史 PIT 回测资格。没有 VERIFIED 公司行为总收益序列时，跨日收益、突破和回撤仍保持缺失。该链路修复不等于 M4/M5 正式评分就绪。


## 7. 免费历史行业成分数据源核验（2026-11-11）

### BigQuant Free 数据表：候选，不等于已准入

公开数据目录将以下两张表列在 Free 会员数据表中：
- `cn_stock_industry_component`：文档描述为逐交易日股票行业成分，包含申万 2021、申万 2014、中信三套分类，页面标注历史范围 2005-01-04 至 2026-11-10。
- `cn_stock_industry_change`：行业变更事件表，页面标注 Free，记录申万 2014、申万 2021、中信分类的进出事件。

来源页面：
- BigQuant Free 会员数据表目录：https://v6.bigquant.com/data/tiers/free
- 行业成分表说明：https://v6.bigquant.com/data/datasources/cn_stock_industry_component
- 行业进出记录说明：https://v6.bigquant.com/data/datasources/cn_stock_industry_change

已核实的文档边界：
- 行业成分表的 `date` 是交易日行业归属记录；同一股票、同一行业体系每天一行。文档指出 SW2014 在 2023 年后部分新股字段为空，CS 历史上也存在大量空值；SW2021 在文档示例日期覆盖相对完整，因此优先核验 SW2021。
- 行业进出表只在变更日期产生事件，不是每日快照；新上市股票首次进入成分表时不产生进入事件。因此不能单独用事件表从空白状态重建所有股票完整行业历史。
- Free 目录只证明数据表被列入 Free 层级；尚未验证 GitHub Actions 中的 SDK 登录、实际查询权限、额度/限流、许可条款和长期可用性。

**关键 PIT 限制：** 两张表公开字段均未提供历史记录首次向用户可用的时间戳或供应商修订版本历史。历史交易日 `date` 不能直接当作 `available_time`。因此：
1. 可以把该表作为历史行业分类覆盖与变更一致性研究的候选来源；
2. 不能把历史行直接送入 `select_pit_industry_membership` 并伪造当时已知时间；
3. 若未来通过免费权限接入，只能从首次实际采集日起保存原始响应、抓取时间、来源版本/内容哈希，并把可用时间标为真实采集时间；该前瞻档案不能自动补成更早年份的 PIT；
4. 只有在供应商能证明历史首次发布/可用时间，或独立官方公告能支持该时间时，才允许把相应历史区间升级为历史 PIT。

### 官方证监会行业分类结果：有限交叉核验

证监会公开页面列出上市公司行业分类季度结果，当前页面可见范围为 2017 年至 2021 年部分季度，并显示每份结果的发布日期。该来源免费且具官方出处，但时间覆盖不连续、频率为季度，分类口径也不等同于申万行业体系；可用于抽样交叉核验，不能单独支撑每日行业归属序列。

来源：https://www.csrc.gov.cn/csrc/c100103/common_list.shtml

### 当前准入结论

BigQuant Free 是目前发现的较有价值的历史行业成分候选，但尚未完成账户/SDK 权限和真实数据下载验证；即使下载成功，历史首次可用时间仍缺失。**行业相对强度与残差强度继续保持 BLOCKED，不接入 M5，不生成正式 A/B/C 信号。**


### BigQuant SDK 免费使用边界补充核验（2026-11-11）

进一步核对官方会员说明与官方客服答复后，不能把“数据表出现在 Free 目录”理解为“GitHub Actions 可永久免费调用”：

- 官方会员说明列出 Free SDK 的日行情历史范围为最近 3 年（不含最近 1 周），行情 quota 每周 300 万（按返回记录数 × 字段数计量），但基础数据 quota 标注为不开放。
- 官方问答中，平台客服针对 SDK 查询权限明确回复：可申请 1 周免费 SDK 试用，后续使用需要付费开通；具体套餐和额度需另行咨询。
- 行业成分表虽然出现在 Free 数据目录中，但公开材料没有证明它属于 Free SDK 可长期调用的日行情额度，也没有证明可从无付费的 GitHub Actions 外部环境持续读取。

来源：
- 会员与 SDK quota 说明：https://v6.bigquant.com/pricing
- Free 数据表目录：https://v6.bigquant.com/data/tiers/free
- 官方客服关于 SDK 试用与后续付费的答复：https://fund.bigquant.com/wiki/doc/j8VaVOtB5g

**决策：** BigQuant 不再列为符合“长期零成本、可由 GitHub Actions 自动调用”要求的可用数据源。只保留为文档研究候选；不添加 SDK 依赖、不要求用户注册或开通试用、不触发付费。即使未来短期试用成功，也不得把试用期数据权限视为长期生产可用性。


### 行业成分快照批次与前瞻选择（2026-11-12）

当前行业成分采集为每次完整函数调用生成唯一 `snapshot_id`，同一调用中不同板块的记录共享该批次 ID；每个板块仍保留实际响应完成时的 `observed_at` 与 `available_time`。归档去重键包含 `snapshot_id`，因此同一天多次采集即使成员未变化，也会留下独立批次，不会把不同采集时点合并。

`src/model/m4_industry_observations.py` 提供独立于历史 PIT selector 的前瞻观察 selector：
- 只接受 `snapshot_scope=current_membership_observation_only` 且 `historical_pit_eligible=false` 的检索时快照；
- 以批次为单位选择决策时点前最新且未超龄的完整快照，不跨批次拼接；
- 批次携带预期行业板块数量；若实际返回板块数量不足，即使股票覆盖看似完整也 fail closed；
- 最新可见批次覆盖不足、存在重复成员关系、时间戳无效或超龄时 fail closed，不回退到旧批次；
- 保留一只股票同时属于多个行业的多对多关系；
- 输出始终标记 `historical_pit_eligible=false`，不得输入历史 PIT 回测或据此推造历史 `valid_from/valid_to`。

这只是从首次持续归档之后建立前瞻行业观察序列，不补齐采集开始前的行业历史，也尚未接入 M5 正式评分。

### 退市历史恢复工作流触发隔离（2026-11-12）
退市历史恢复工作流对所有已配置事件先运行一个轻量触发确认任务；实际历史恢复任务仍只允许定时或手动触发，并且仅在 `main` 分支执行。普通代码 Push 不会启动退市数据回补，避免每次提交都消耗恢复任务资源。
