# tick-stock-panel 接入评估（2026-11-10）

## 结论

暂不把 tick-stock-panel（TSP）整体部署进本项目，也不把其策略或 AI 结论作为 FHM-100 信号。保留当前 GitHub Actions + PushPlus 的轻量运行架构。TSP 可作为独立研究工作台；后续只在数据质量、授权和点时口径通过验收后，考虑复用其数据适配思路或导入标准化数据。

## 已核实能力与限制

- TSP 文档说明 TickFlow 无 Key 的 None 模式可使用历史日 K；当日数据通常在收盘后 1–2 小时可用。
- 实时全市场、分钟 K、盘口和财务等能力取决于订阅档位或其他数据源，不应视为免费能力。
- 支持 daily、adj_factor、realtime、minute、full_minute、financial 等自定义数据集接入；深度盘口暂不属于自定义数据源契约。
- 自定义源负责字段、单位、日期和证券代码归一化；上层策略应依赖标准数据契约。
- 项目采用本地持久化和 Docker 服务形态，不适合作为 GitHub Actions 中短时运行的直接依赖。Actions 无法访问用户手机或个人电脑上的 localhost 服务。

## 对 FHM-100 的接入门槛

1. 每条行情和公司行为数据必须有来源、版本、可用时间及可追溯快照 ID。
2. 复权因子/公司行为必须可核验；未核验数据不得用于正式收益标签、评分或回测。
3. 历史行业成分必须按当时有效日期与可用时间还原，不能用当前行业分类回填历史。
4. 分钟、盘口、资金流和涨跌停开板等因子，只有数据源确实提供对应粒度和字段时才计算；不得用日成交额替代订单流。
5. 所有新数据源必须先通过字段、单位、缺失率、复权、停牌/涨跌停、时间戳和历史样本抽查，再进入模型。
6. TSP 的策略、回测或 AI 输出不得改变 FHM-100 原始权重、风险门槛和交易规则。

## 推荐实施顺序

- **当前**：维持 stock1 轻量任务；完善 M4 因子原语和 PIT 校验。
- **下一阶段**：建立统一 provider 接口与数据源健康检查；先接入并验证免费历史日 K 的可用性与稳定性。
- **之后**：只有在取得可靠的复权因子、历史行业成分和公司行为数据后，才开展正式回测与模型评分联调。
- **可选**：如需可视化、策略研究和本地回测，可单独部署 TSP；它不是 stock1 自动推送任务的运行前提。

- 未证明免费模式提供完整复权因子、历史行业成员或逐笔/盘口数据。
