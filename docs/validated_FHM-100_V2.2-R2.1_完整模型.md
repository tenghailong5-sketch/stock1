# FHM-100 完整模型 V2.2

**研究设计版**

**可编程规格框架**

**模型定位**：中国A股短线量化选股与交易决策系统，主要持有周期1—5个交易日，目标是在控制尾部风险和交易成本后，寻找具有正预期净收益的交易机会。

**适用范围**：沪深主板、创业板；排除科创板、北交所。模型面向激进型短线策略，但不允许以高收益预期为理由突破风险预算。

**重要说明**：以下是整合此前讨论的完整规则和待验证参数，不代表已经完成全市场历史回测，也不代表这些参数已被证明最优。文中示例数值均为模型初始假设。

---

## 第一部分：模型总体结构

模型分为九个模块：

| 模块 | 名称 | 核心任务 |
| --- | --- | --- |
| M1 | 数据管理 | 建立可信、无未来数据的历史数据 |
| M2 | 股票池过滤 | 排除不适合交易的股票 |
| M3 | 市场状态识别 | 判断当前市场适合哪类策略 |
| M4 | 因子计算 | 计算资金、行业、价格、成交、事件等指标 |
| M5 | 三策略评分 | 分别识别趋势、事件、反转机会 |
| M6 | 收益风险预测 | 预测上涨概率、收益分布和下行风险 |
| M7 | 交易执行 | 决定买入、卖出、放弃及成交价格 |
| M8 | 组合风险控制 | 分配仓位、控制集中度和总体风险 |
| M9 | 回测及监控 | 检验有效性、监控模型失效 |

总体流程：

```
M1 数据管理
M2 股票池过滤
M3 市场状态识别
M4 因子计算
M5 A/B/C策略独立评分
M6 收益概率与风险预测
M7 交易执行过滤
M8 组合风险分配
M9 回测、监控与版本更新
```

## 第二部分：M1 数据管理

### 1. 必须使用的数据

| 数据类别 | 核心字段 | 用途 |
| --- | --- | --- |
| 股票基础资料 | 代码、上市日期、板块、ST状态 | 股票池 |
| 日线行情 | 开高低收、成交量、成交额 | 趋势与价格结构 |
| 复权数据 | 复权因子、除权除息信息 | 收益计算 |
| 行业数据 | 行业分类、行业指数 | 行业相对强度 |
| 指数数据 | 上证、深证、创业板、沪深300 | 市场状态 |
| 涨跌停数据 | 涨停价、跌停价、触及状态 | 事件策略 |
| 资金流数据 | 主动买卖代理、大单净额等 | 增量因子研究 |
| 公告新闻 | 发布时间、内容、事件分类 | 催化和风险 |
| 交易制度 | 涨跌幅限制、停牌、交易日历 | 成交模拟 |

### 2. 数据质量要求

必须执行以下检查：

- 同一证券同一交易日不能出现重复行情记录。
- 价格、成交量、成交额不得出现明显逻辑矛盾。
- 除权、送转、分红必须正确处理。
- 停牌日不得填造可交易价格。
- 公告必须按照实际公开时间进入模型，不能使用未来才知道的信息。
- 行业分类应保存历史版本，不能拿今天的行业分类覆盖全部历史。
- ST状态、上市状态和交易制度均需按历史日期还原。

### 3. 未来函数控制

所有因子必须满足：

$$
Feature_{i,t}=f(Data_{\leq t})
$$

也就是在T日收盘产生信号，只能使用T日收盘时已经公开的数据。

如果某条公告在T日收盘之后发布，就不能用于T日收盘信号。

财务指标必须使用实际披露时间，而不是报告期结束日期。

### 4. 数据分级

**A级**

可直接用于核心模型：历史日线、指数、成交额、行业指数、历史交易制度。

**B级**

需验证后使用：资金流、新闻情绪、主力资金、大单成交等供应商加工数据。

**C级**

只能作为辅助：社交媒体热度、未经证实的传闻、来源不明的资金流截图。

B级数据必须进行供应商口径一致性测试；C级数据不能单独触发买入信号。

## 第三部分：M2 股票池过滤

以下是V2.2初始过滤条件。

| 过滤项目 | 初始规则 |
| --- | --- |
| 交易市场 | 沪深主板、创业板 |
| 科创板 | 排除 |
| 北交所 | 排除 |
| ST及退市风险 | 排除 |
| 上市时间 | 不足120个交易日排除 |
| 停牌 | 当日不可交易时排除 |
| 流动性 | 过去20日平均成交额低于1亿元排除 |
| 重大风险 | 重大不确定事项、重大违法风险等排除 |
| 数据异常 | 行情和复权数据不完整时排除 |
| 一字涨停 | 不允许假设能够买入 |

股票池过滤是硬门槛，不计入100分。被排除的股票即使其他因子表现很好，也不能重新进入交易候选。

## 第四部分：M3 市场状态识别

市场状态分为三种。

### 1. 市场指标

计算：

- 指数相对20日均线的位置；
- 指数相对60日均线的位置；
- 过去20日指数收益；
- 市场上涨股票比例；
- 涨停股票数量；
- 跌停股票数量；
- 市场成交额相对20日均值；
- 市场波动率。

定义：

$$
Breadth_t=\frac{上涨股票数量}{上涨股票数量+下跌股票数量}
$$

$$
LimitBalance_t=涨停数量-跌停数量
$$

市场指标必须使用当时可获得的股票池，不把后来退市的股票从历史样本中删除。

### 2. 市场状态

| 状态 | 判断逻辑 | 策略安排 |
| --- | --- | --- |
| 风险偏好上升 | 指数趋势、市场广度和成交活跃度共同改善 | A、B、C正常评估 |
| 震荡分化 | 趋势和广度信号不一致 | 提高准入要求，优先研究C |
| 风险偏好下降 | 指数趋势走弱、广度恶化、跌停增加 | 降低仓位或暂停开仓 |

具体数值阈值通过训练。不允许根据未来收益选择历史上的市场状态。

## 第五部分：M4 因子计算

所有因子先进行数据清洗，再进行横截面标准化。

统一使用百分位排名：

$$
P_{i,t}=PercentileRank(X_{i,t})
$$

如果某因子越低越好，应先反向处理。行业因子与个股因子使用不同的比较范围。

### 1. 行业相对强度

$$
RS_{industry,5}=R_{industry,5}-R_{market,5}
$$

同时计算20日版本。

行业强度排名越靠前，说明所属行业近期表现相对突出。

### 2. 个股残差强度

$$
R_{res,5}=R_{stock,5}-\beta_mR_{market,5}-\beta_iR_{industry,5}
$$

其中：

- $\beta_m$：个股对市场收益的历史敏感度；
- $\beta_i$：个股对行业收益的历史敏感度。

Beta使用过去一段时间的滚动窗口估计，不能使用未来数据。

该因子用于判断个股是否真正跑赢行业和市场。

### 3. 价格结构

定义：

$$
CLV=\frac{Close-Low}{High-Low}
$$

$$
BodyStrength=\frac{Close-Open}{High-Low}
$$

- CLV接近1：收盘靠近最高价。
- CLV接近0：收盘靠近最低价。
- BodyStrength为正：阳线实体较强。
- BodyStrength为负：阴线实体较弱。

当High等于Low时，设为缺失值。

同时计算：

- 5日、10日、20日收益；
- 相对行业收益；
- 突破过去20日高点的幅度；
- 上影线比例；
- 近期最大回撤；
- 回撤持续时间。

### 4. 成交质量

定义：

$$
LQ=\frac{Amount_t}{MA_{20}(Amount)}
$$

其中Amount为当日成交额。

同时计算：

- 成交额5日均值/20日均值；
- 成交量变化；
- 换手率；
- 价格上涨时的成交确认；
- 放量滞涨；
- 缩量回撤。

成交额放大不是自动加分。必须结合价格变化判断。

### 5. 短期回撤因子

$$
Pullback=\frac{Close_t}{RecentHigh}-1
$$

回撤幅度应结合此前趋势、成交变化和止跌确认共同分析。

不能把所有下跌都视为回撤买点。

### 6. 资金流因子

暂时作为待验证模块。

包括：

- 3日净流入；
- 5日净流入；
- 资金流连续性；
- 行业资金流相对强度；
- 大单和小单成交方向。

需要检验其在控制价格、成交额、换手率后是否还有增量预测价值。

如果没有稳定的样本外增量，降低权重或删除。

### 7. 消息催化因子

只纳入有可验证来源的消息：

- 政策正式发布；
- 行业供需变化；
- 公司业绩及预告；
- 订单和产品进展；
- 重大资产重组等事项。

必须区分消息发布时间与实际发生时间。传闻不计为确定性催化。

消息公布后股价已经大幅上涨、后续没有持续反应，不能继续机械加分。

### 8. 涨跌停事件因子

建立独立事件字段：

| 字段 | 定义 |
| --- | --- |
| HitUp | 盘中是否触及涨停 |
| CloseUp | 是否收盘封住涨停 |
| OpenBoard | 是否出现开板 |
| HitDown | 是否触及跌停 |
| CloseDown | 是否收盘封住跌停 |
| GapNext | 次日开盘跳空 |
| RetNext | 事件后收益 |

没有逐笔数据时，不推测开板次数和盘口排队情况。

### 9. 过热及偏离因子

定义行业偏离：

$$
DS=|R_{stock,5}-R_{industry,5}|
$$

计算其过去120个交易日的历史百分位。

初始解释：

- 低于70%：正常观察；
- 70%—90%：检查是否存在真实催化；
- 高于90%：不允许仅凭涨幅追逐；
- 高偏离且缺少催化：重点观察过热风险。

这组阈值是实验参数，不是学术研究直接给出的最佳阈值。

## 第六部分：M5 三大策略评分系统

三种策略独立评分，不能把不同策略的分数直接当作同一种信号。

统一规则：

$$
Score=\sum_{k=1}^{n}w_kP_k
$$

其中：

- $w_k$：因子权重；
- $P_k$：标准化后的因子得分，范围0—100；
- 权重总和为100。

风险硬门槛不进入这个公式，避免高分抵消风险。

### A策略：强势趋势延续

主要预测周期：3—5日

| 因子 | 权重 | 主要指标 |
| --- | --- | --- |
| 行业相对强度 | 20 | 行业5日、20日超额收益 |
| 个股残差强度 | 25 | 市场和行业调整后的个股收益 |
| 价格结构 | 15 | 突破、CLV、上影线、回踩确认 |
| 成交质量 | 15 | 成交额变化、换手、量价配合 |
| 市场环境 | 15 | 市场趋势、广度、波动 |
| 消息催化 | 10 | 可验证的行业和公司事件 |
| 合计 | 100 | |

初始筛选规则：

1. 行业强度处于行业横截面前30%。
2. 个股残差强度处于股票横截面前20%。
3. 20日平均成交额不低于1亿元。
4. 价格突破或回踩后出现确认。
5. 不能处于明显放量滞涨或连续冲高回落状态。
6. 次日开盘跳空超过3%时不追买。

### B策略：涨跌停事件

主要预测周期：1—3日，单独统计5日

B策略不使用普通趋势评分直接替代事件评分。

| 因子 | 权重 | 主要指标 |
| --- | --- | --- |
| 事件类型 | 20 | 触板、封板、开板、跌停事件 |
| 事件前趋势 | 15 | 事件前5日残差收益 |
| 事件成交结构 | 20 | 事件日成交额、换手、价格结构 |
| 行业和市场环境 | 15 | 行业强度、市场广度 |
| 次日价格行为 | 20 | 跳空、开盘后成交及价格确认 |
| 风险 | 10 | 流动性、重大公告、过热程度 |
| 合计 | 100 | |

注意：次日价格行为只能用于次日盘中重新评估，不能提前写入前一日收盘时的信号。

B策略至少拆成四个子样本：

- 触及涨停但未封板；
- 收盘封住涨停；
- 触及跌停但未封板；
- 收盘封住跌停。

每个子样本单独检验。不同事件不能简单合并。

### C策略：强势股回撤反转

主要预测周期：1—3日

| 因子 | 权重 | 主要指标 |
| --- | --- | --- |
| 行业强度 | 15 | 行业5日、20日相对收益 |
| 回撤前强度 | 15 | 回撤前5日残差收益 |
| 回撤与反转结构 | 25 | 回撤幅度、时间、止跌确认 |
| 成交质量 | 20 | 回撤缩量、承接、成交额 |
| 市场环境 | 15 | 市场广度、指数趋势 |
| 催化与风险 | 10 | 消息确认、趋势破坏风险 |
| 合计 | 100 | |

初始筛选条件：

- 回撤前5日残差收益为正；
- 最近1—2日回撤约0.5%—4%；
- 回撤期间成交量不高于此前5日平均量的80%；
- CLV及价格结构出现止跌确认；
- 行业没有明显转弱；
- 不存在重大利空和流动性异常。

以上条件均需单独做参数敏感性检验，不能认定为固定最优条件。

### 三策略分数如何使用

| 分数 | 初始处理 |
| --- | --- |
| 90—100 | 重点研究，但仍需通过全部交易过滤 |
| 80—89 | 进入候选名单 |
| 70—79 | 观察，不自动交易 |
| 低于70 | 暂不进入交易候选 |

80分不是买入指令。即使达到90分，也必须通过收益预测、执行过滤和组合风险控制。

## 第七部分：M6 收益与风险预测引擎

这一部分是V2.2的核心升级。

评分模型负责排序，预测模型负责估计交易价值，两者不能混为一谈。

### 1. 每只候选股票输出的预测值

| 输出字段 | 含义 |
| --- | --- |
| P_up_1 | 未来1日净收益为正的概率 |
| P_up_3 | 未来3日净收益为正的概率 |
| P_up_5 | 未来5日净收益为正的概率 |
| E_R_1 | 未来1日预期净收益 |
| E_R_3 | 未来3日预期净收益 |
| E_R_5 | 未来5日预期净收益 |
| Q10_R_3 | 未来3日净收益第10百分位 |
| Q10_R_5 | 未来5日净收益第10百分位 |
| MAE_3 | 未来3日最大不利波动 |
| MAE_5 | 未来5日最大不利波动 |
| MFE_3 | 未来3日最大有利波动 |
| MFE_5 | 未来5日最大有利波动 |

其中收益必须按真实可执行的买卖时点计算，并扣除费用和滑点。

### 2. 预测模型结构

建议采用两阶段方案：

第一阶段：可解释基准模型

- 逻辑回归：预测收益为正的概率；
- 线性或岭回归：预测收益均值；
- 分位数回归：预测收益分布的下尾风险。

第二阶段：非线性模型对照

- LightGBM或其他梯度提升树；
- 与第一阶段模型在相同样本、相同标签、相同成本假设下比较；
- 只有样本外表现稳定改善，才允许替换基准模型。

不建议一开始就使用复杂深度学习。短线A股数据噪声较大，模型越复杂，越需要严格防止过拟合。

### 3. 概率校准

假设模型对100笔交易预测上涨概率为70%，实际上涨比例应该接近70%。

采用：

- Brier Score；
- Log Loss；
- 概率分组校准曲线；
- 不同市场状态下的校准结果。

如果概率预测不可靠，就不能把它直接用于仓位分配。

### 4. 交易优势计算

$$
Edge_h=E(R_h)-Cost_h
$$

$$
Q_h=\frac{Edge_h}{\max(Risk_h,\epsilon)}
$$

这里的Cost包括：

- 佣金；
- 印花税；
- 过户费等适用费用；
- 买卖价差；
- 滑点；
- 冲击成本；
- 无法成交造成的执行损失。

Risk不能只使用历史标准差，还要参考收益下分位数、MAE和跳空风险。

交易门槛：

- Edge不大于0：不交易。
- Edge为正但低于预测误差范围：不交易。
- Edge为正且风险可承受：进入执行过滤。
- 预测概率不稳定：降低信任度，不能放大仓位。

## 第八部分：M7 交易执行系统

### 1. 买入条件

T日收盘生成候选信号后，T+1日执行。

必须同时满足：

1. T日对应策略评分达到要求。
2. 预期净收益为正。
3. 预测优势超过模型误差。
4. 次日开盘跳空不超过3%。
5. 盘中价格结构没有破坏原信号。
6. 成交额和流动性允许执行。
7. 止损风险和组合风险均在预算内。
8. 没有新的重大公告或突发风险。

任一条件不满足，放弃交易。

### 2. 买入价格模拟

不能默认以次日开盘价无条件成交。

回测至少需要两种执行情景：

- 保守情景：开盘后确认价格和成交量，按照可执行价格买入。
- 压力情景：在保守情景基础上增加滑点和冲击成本。

如果没有分钟线或逐笔数据，只能对日线策略使用明确标注的成交假设，不能伪装成精确盘中成交模拟。

### 3. 卖出条件

卖出原因分为五类：

| 类型 | 处理 |
| --- | --- |
| 结构止损 | 关键支撑破坏，执行可成交卖出 |
| 趋势衰退 | 个股持续弱于行业，重新评估 |
| 资金和成交恶化 | 连续出现负面成交结构 |
| 止盈 | 达到策略目标或预期收益衰减 |
| 时间退出 | 到达策略持有期限 |

初始测试止盈参数可使用+8%至+12%，但不能把它当作已经优化的固定目标。

初始测试止损距离可比较5%、6%、8%等不同方案，但仓位必须同步调整，不能用固定仓位套用不同止损幅度。

### 4. T+1特殊处理

必须严格执行：

- 当日买入不能当日卖出；
- 买入后最早下一个交易日才能卖出；
- 买入日出现跌停或突发利空，不能假设当日止损成功；
- 次日跳空越过止损位，按真实可成交价格计算；
- 跌停无有效卖出成交时，继续持有并记录实际延迟退出。

## 第九部分：M8 组合仓位与风险控制

### 1. 单笔风险预算

此前设定：

- 短线资金：100,000元；
- 单笔计划最大亏损：2,000元；
- 总计划风险上限：3,000元；
- 同时持仓最多2只。

仓位计算：

$$
Position=\frac{RiskBudget}{StopDistance+GapBuffer+CostBuffer}
$$

示例：

| 项目 | 假设值 |
| --- | --- |
| 单笔风险预算 | 2,000元 |
| 止损距离 | 5% |
| 跳空缓冲 | 2% |
| 成本和滑点缓冲 | 0.3% |
| 计算仓位 | 约27,397元 |

这是模型预算值，不是实际最大亏损保证。

### 2. 组合风险

如果两只股票同属一个热门行业，不能把风险简单相加后认为彼此独立。

组合控制需要计算：

- 行业集中度；
- 主题集中度；
- 历史收益相关性；
- 共同消息风险；
- 市场下跌时的联合损失；
- 隔夜跳空风险。

建议初始规则：

- 最多持有2只；
- 不因同一行业出现多个高分信号而增加集中度；
- 全部持仓计划风险不超过3,000元；
- 市场风险偏好下降时，减少新开仓；
- 无法合理估算尾部风险时，不满仓。

### 3. 组合优化目标

$$
\max \left(E(R_{portfolio})-\lambda TailRisk_{portfolio}\right)
$$

其中TailRisk可采用预期损失CVaR等方法估计。

组合优化必须考虑交易约束、最小交易单位、持仓限制及A股可卖数量，不能只做数学上的连续权重优化。

## 我的最终判断

FHM-100 V2.2已经形成一套完整的研究和交易系统框架，但现在最缺少的不是更多指标，而是三项实证工作：

## 第二部分：方法论级修正（最高优先）

### 方法一：前复权价格构成未来函数【硬规则·R1 新增】

基准版 M1 第 3 节要求 $Feature_{i,t}=f(Data_{\leq t})$，但未规定复权口径。**前复权价格会随后续每一次除权除息回溯改写历史数值**：同一根 2020 年 K 线，在 2021 年分红前后取到的前复权收盘价不同。若回测用"今天下载的前复权序列"计算 2020 年信号，等于把未来除权信息带入了历史特征，直接违反未来函数控制。

补充规则（写入 M1 第 3 节）：

1. **收益计算一律使用后复权价**（`close_adj_back = close × adj_factor`），后复权只依赖 `Data_{\leq t}` 的累计因子，不回溯改写。
2. **涨跌停价、涨跌幅、跳空一律使用不复权价 + 当日除权除息信息**，因为交易所限价基于不复权前收盘价。
3. **成交额、成交量、换手率不复权**。
4. **禁止**用"当前时点重新下载的全历史前复权序列"作为回测输入；如数据源只提供前复权，必须转换为 `不复权价 + adj_factor` 两列后再入库。
5. 数据校验新增一条：`adj_factor` 必须按 `ex_date` 单调递增（仅除权日跳变），非除权日跳变即判数据异常，触发 M2「数据异常」排除。

> 这条不改变任何因子公式，只锁定价格口径；若不锁定，M4 全部价格类因子与 M6 全部收益标签都不可信。

### 方法二：M3 市场状态可计算化（解除四模块连锁空转）【R1 新增】

基准版 M3 的"具体数值阈值通过训练"为空，导致 M5「市场环境」权重（A15／B15／C15）、M6「不同市场状态下的校准结果」、M8「风险偏好下降时减少新开仓」、M7 准入调整全部无输入。补充如下，**全部只使用 T 日及之前数据**，严格遵守"不允许根据未来收益选择历史上的市场状态"。

**四个分量**（均为过去 60 日百分位或 0/1 指示，【初始假设·待验证】）：

| 分量 | 定义 | 取值 |
| --- | --- | --- |
| `S_trend` | $0.5\cdot\mathbf{1}[Close_{idx}>MA20] + 0.5\cdot\mathbf{1}[MA20>MA60]$ | {0, 0.5, 1} |
| `S_breadth` | $Breadth_t$ 的过去 60 日百分位 | [0,1] |
| `S_activity` | $Amount_t/MA20(Amount)$ 的过去 60 日百分位 | [0,1] |
| `S_limit` | $LimitBalance_t$ 的过去 60 日百分位 | [0,1] |
| `S_vol` | 市场 20 日波动率的过去 60 日百分位（风险扣减项） | [0,1] |

$$
StateScore = 0.35S_{trend}+0.25S_{breadth}+0.20S_{activity}+0.20S_{limit}-0.10S_{vol}
$$

**状态判定**（【实验参数·需敏感性检验】）：

| 状态 | 判定条件 | 策略安排（对应基准版 M3 表） | `position_scale` |
| --- | --- | --- | --- |
| RISK_ON 风险偏好上升 | $StateScore\geq0.60$ 且 $S_{trend}\geq0.5$ | A、B、C 正常评估 | 1.0 |
| NEUTRAL 震荡分化 | 其余 | 提高准入要求（候选门槛 80→85），优先研究 C | 0.7 |
| RISK_OFF 风险偏好下降 | $StateScore\leq0.35$ 或 $S_{limit}\leq0.20$ 或 跌停数 > 0.5×涨停数 | 降低仓位或暂停开仓 | 0（暂停新开仓） |

补充三条【硬规则】：

- **切换冷却**：状态需连续 2 个交易日满足条件才切换，避免单日噪声导致策略反复摇摆；状态在 T 日收盘确定、T+1 生效。
- **禁止回填**：阈值与权重只能用 `2016—2022` 训练段确定并冻结，**不得**依据 T+1…T+h 收益或样本外表现反推历史状态标签（呼应基准版禁令）。
- **输出字段**：`market_state_t ∈ {RISK_ON, NEUTRAL, RISK_OFF}`、`StateScore_t` 写入 `index_daily`，供 M5／M6／M7／M8 直接引用。

**M5「市场环境」因子的 0—100 映射**（基准版未定义，【初始假设·待验证】）：设 $z$ 为 `StateScore` 在所属状态区间内归一化到 [0,1] 的值，则

$$
P_{market}=\begin{cases}
75+25z & \text{RISK\_ON}\\
40+35z & \text{NEUTRAL}\\
10+30z & \text{RISK\_OFF}
\end{cases}
\quad \text{clamp 到 }[0,100]
$$

这样 M5 统一的 $Score=\sum w_kP_k$ 才能真正算出数值，M6 也可按 `market_state_t` 分组出校准曲线。

### 方法三：双持仓风险分配（修正 4,000 > 3,000）【R1 新增】

基准版 M8 同时规定「单笔计划最大亏损 2,000 元」「总计划风险上限 3,000 元」「同时持仓最多 2 只」，但 2×2,000 = 4,000 > 3,000，缺分配算法。**R1 不修改这三个数值**，只补一条分配规则：

$$
RiskBudget_2=\min\left(2000,\ 3000-RiskBudget_1\right)
$$

| 方案 | 规则 | 优点 | 缺点 | 推荐 |
| --- | --- | --- | --- | --- |
| S1 等权缩放 | 两只各 $\min(2000, 3000/2)=1500$ | 简单、永不超限 | 忽略信号质量差异 | — |
| S2 质量优先 | 按 $Q_h$ 降序：首只 2,000，次只 1,000 | 优势大的多分配 | 次只仓位偏小 | ★ 推荐默认 |
| S3 相关性折减 | 在 S2 上叠加：同行业或相关系数 >0.6 时，次只预算 ×0.5 | 呼应 M8 相关性约束 | 需滚动估计相关性 | ★ 与 S2 叠加启用 |

补充【硬规则】：

- 单只实际仓位 $Position_i=\dfrac{RiskBudget_i}{StopDistance_i+GapBuffer_i+CostBuffer_i}$，且 $\sum_i RiskBudget_i\leq3000$ **为硬约束，优先级高于任何评分**。
- 若首只已用满 2,000 且次只预算 < 600 元（【实验参数】），则放弃次只，不强行凑满 2 只。
- 方法二的 `position_scale` 直接作用于 $Position_i$：$Position_i^{final}=Position_i\times position\_scale$；RISK_OFF 时新开仓一律为 0。
- 相关性估计使用过去 60 日**已实现**日收益，仅用 `Data_{\leq t}`。

### 方法四：`E_R_h` 与 `Edge_h` 成本口径统一（避免重复扣费）【R1 新增】

基准版 M6 第 1 节规定「输出字段 `E_R_h` 为未来 h 日预期**净**收益」，且「收益必须按真实可执行的买卖时点计算，并扣除费用和滑点」；但 M6 第 4 节又定义 $Edge_h=E(R_h)-Cost_h$。若 $E(R_h)$ 取的是已扣费的 `E_R_h`，则成本被扣两次，会系统性低估 Edge，把本可交易的机会误判为「Edge ≤ 0：不交易」。

**R1 统一口径（推荐默认 D9）**：

| 字段 | 定义 |
| --- | --- |
| `R_h^net`（训练标签） | 已扣全部成本，唯一收益口径（见 R1-2） |
| `E_R_h`（预测输出） | 对 `R_h^net` 的预测，**本身即净收益** |
| `Edge_h` | $Edge_h\equiv E\_R\_h$，**不再额外减** `Cost_h` |
| `E_R_h^gross`、`Cost_h_est` | 并列保留在 `signal_log` 中，供逐笔复核成本假设，**不参与门槛判定** |

补充【硬规则】：

- 基准版公式 $Edge_h=E(R_h)-Cost_h$ **保留不删**，此处仅明确 $E(R_h)$ 应理解为**毛收益预测** $E\_R\_h^{gross}$；当模型只输出净收益时两式等价（$E\_R\_h^{net}=E\_R\_h^{gross}-Cost_h$），**不得**用净收益再代入原式。
- 若选择保留「毛收益 − 成本」写法，则 M6 输出表须同时给出 `E_R_h^gross` 与 `Cost_h`，门槛判定只用 `E_R_h^net`。
- 该口径直接决定 M6 交易门槛与 M7 条件 2／3，须在回测引擎中**固定为一处实现**，禁止两处各扣一次成本。

### R1-2 预测标签与收益口径（G3）【R1 新增】

**成交时点锚**（【初始假设·待验证】）：

| 变量 | 定义 |
| --- | --- |
| `P_buy` | T+1 保守情景可执行价（见 R1-6），非无条件开盘价 |
| `P_sell_h` | 持有 h 个交易日后收盘价；若期间触发止损/止盈/时间退出，取实际可成交退出价 |
| `h` | A：3 与 5；B：1 与 3（5 日单独统计）；C：1 与 3 |

$$
R_h^{net}=\frac{P_{sell,h}(1-c_{sell})}{P_{buy}(1+c_{buy})}-1
$$

其中 $c_{buy}$、$c_{sell}$ 按 R1-3 定义，**已包含**佣金、印花税、过户费、买卖价差、滑点与冲击成本；`Cost_h = c_buy + c_sell` 与之同源，**不重复扣减**（口径统一见方法四）。

| 标签 | 定义 |
| --- | --- |
| `P_up_h` | $\mathbf{1}[R_h^{net}>0]$（逻辑回归标签） |
| `E_R_h` | $R_h^{net}$（线性/岭回归标签） |
| `Q10_R_h` | $R_h^{net}$ 的条件第 10 分位（分位数回归标签） |
| `MAE_h` | $\min_{1\leq s\leq h}(Low_s/P_{buy}-1)$，无分钟线时用日最低价代理 |
| `MFE_h` | $\max_{1\leq s\leq h}(High_s/P_{buy}-1)$，用日最高价代理 |

补充【硬规则】：

- **T+1 与止损交互**：h 日内触发止损则标签按实际退出价截断、持有期提前结束；买入日跌停不得假设止损成功，按 M7 第 4 节顺延并记录 `exit_delay_days`。
- **标签时间隔离**（落实 M9 第 4 节「防止窗口重叠泄漏」）：`purge = h+1` 个交易日、`embargo = 1` 个交易日；训练样本末日与验证样本首日之间必须留空此窗口。
- `R_h^{net}` 全部按**真实可执行买卖时点**计算并扣费，禁止用"T 日收盘→T+h 日收盘"的账面收益冒充（呼应基准版 M6 第 1 节）。
- 净收益为**绝对净收益**；超额收益在 M9 单列，不混用为训练标签（D2）。

### R1-3 成本参数与 `Cost_h` 展开（G4）【初始假设·待验证】

| 项目 | 初始假设 | 说明 |
| --- | --- | --- |
| 佣金 | 买/卖各 0.025%（万 2.5），单笔最低 5 元 | **须按开户券商实际费率核实** |
| 印花税 | 卖出单边 0.05% | **须按交易所最新规则核实** |
| 过户费 | 双边各 0.001% | **须按最新规则核实** |
| 买卖价差 | 1 个最小报价单位 / 中间价，按价格分档逐笔算 | 不用固定常数 |
| 滑点 | 保守 5bp／压力 15bp（双边） | 【实验参数】 |
| 冲击成本 | $impact = k\sqrt{participation}$，$k=0.001$，$participation=order\_value/ADV20\leq1\%$ | 参与度超 1% 时按 M7 条件 6 放弃 |
| 无法成交损失 | 不记为负收益，单列「机会成本」与放弃率 | 与 M9「成交成功率」口径一致 |

$$
c_{buy}=comm+transfer+\tfrac{spread}{2}+slip+impact,\quad
c_{sell}=comm+stamp+transfer+\tfrac{spread}{2}+slip+impact
$$

$$
Cost_h=c_{buy}+c_{sell}
$$

补充【硬规则】：`Cost_h` **逐笔按价格、参与度、情景计算**，不得在回测里写死一个常数。上表费率合计仅作量级校验（保守情景约 0.2%—0.3%，压力情景约 0.45%—0.6%），上线前必须逐项核实；费率未核实前，回测结论不得用于验收。

### R1-4 `Risk_h`／`Q_h` 合成与量化门槛（G5）【R1 新增】

**主口径（推荐默认，max 版）**：

$$
Risk_h=\max\left(|Q10\_R_h|,\ |MAE_h|,\ GapRisk_h,\ z\sigma_h\right),\qquad z=1.65
$$

$$
Q_h=\frac{Edge_h}{\max(Risk_h,\ \epsilon)},\qquad \epsilon=0.005
$$

| 变量 | 定义 |
| --- | --- |
| `GapRisk_h` | 过去 250 日 $|Open_{t+1}/Close_t-1|$ 的 90 分位（纯历史数据） |
| `σ_h` | 过去 60 日 $R_h^{net}$ 的标准差（仅作下限保护，不单独作为风险度量） |

对照口径（加权版，$0.4|Q10|+0.3|MAE|+0.3GapRisk$）在 M9 中作为敏感性检验项，**不替代主口径**；max 版更保守，符合"不允许以高收益预期突破风险预算"。

**交易门槛的可计算版本**（对应基准版 M6 第 4 节四条）：

| 原门槛 | R1 判定式 |
| --- | --- |
| Edge ≤ 0：不交易 | $Edge_h=E(R_h)-Cost_h\leq0$ → 放弃 |
| Edge 为正但低于预测误差范围：不交易 | $Edge_h\leq k\cdot SE(Edge_h)$，$k=1.0$【实验参数】→ 放弃 |
| Edge 为正且风险可承受：进入执行过滤 | $Edge_h>k\cdot SE(Edge_h)$ 且 $Q_h\geq Q_{min}=0.3$【实验参数】且 $Risk_h\leq StopDistance+GapBuffer+CostBuffer$ |
| 预测概率不稳定：降低信任度 | 该股所属 `market_state` 概率分组的 Brier Score 高于训练集 90 分位 → `RiskBudget_i × 0.5`，且不得放大仓位 |

`SE(Edge_h)` 由两阶段模型的预测区间或区块 Bootstrap 给出，禁止用单点估计代替。

### R1-6 成交判定口径与双情景成交价（G8）【R1 新增】

| 情形 | 回测标记 | 是否计入收益 | 计入成交成功率分母 |
| --- | --- | --- | --- |
| T+1 一字涨停（`open=high=low=limit_up`） | `unfillable` | 否 | 是 |
| T+1 高开 >3% | `skipped_gap` | 否 | 是 |
| 封板无法买入 | `unfillable` | 否 | 是 |
| 买入日跌停／突发利空 | `delayed_exit` | 是（按实际延迟退出价） | — |
| 卖出日跌停无有效成交 | `delayed_exit`，记录 `exit_delay_days` | 是（顺延后价格） | — |
| 停牌 | `suspended`，顺延 | 是（顺延后价格） | — |
| 正常成交 | `filled` | 是 | 是 |

$$
成交成功率=\frac{\#filled}{\#filled+\#unfillable+\#skipped\_gap},\qquad 放弃率=1-成交成功率
$$

**成交价公式**（【初始假设·待验证】）：

- 保守情景：$P_{buy}=Open_{T+1}\times(1+slip_{cons})$，前置条件：非一字、非涨停、`participation≤1%`。
- 压力情景：$P_{buy}=P_{buy}^{cons}\times(1+slip_{stress}+impact)$，且冲击成本按 2 倍参与度上限检验。
- **无分钟线／逐笔数据时**，一律标注 `execution_model=DAILY_PROXY`，**不得**声称精确盘中成交模拟（严格落实基准版 M7 第 2 节）。

# 第一章 R2.1-01：决策时间与数据可用时间隔离
**修复对象：R1-5 条件 5、R1-9 日内运行流程中的未来函数风险。**

## 1.1 所有数据必须具有双时间戳

每条可用于模型的数据至少保存：

- `event_time`：数据所描述事件实际发生的时间。
- `available_time`：该数据最早可被策略系统可靠取得的时间。
- `ingest_time`：本系统实际接收时间。
- `revision_time`：供应商修订或更正时间（如有）。

历史回放只能使用在决策时点 `decision_time` 已经可用的数据：

`available_time <= decision_time`

若供应商没有提供历史可用时间或历史版本，不能假设今天下载的修订数据在历史当时已经存在。该字段应标记为 `availability_quality=UNKNOWN`，相关因子不得进入严格无前视回测，除非通过独立证据重建。

## 1.2 两种执行模式必须分离

### 模式 D：日线收盘信号、下一交易日执行

- `T` 日收盘后，只有在日线数据正式发布并通过质量校验后，才生成信号。
- 信号生成时间记录为 `decision_time`，不得伪造为 15:00 整。
- 最早执行时间为 `T+1`。
- `T+1` 的全天 `High/Low/Close` 不得用于 `T+1` 早盘买入资格判断。
- 日线模式不得使用“`Low_T+1` 高于止损线且 `Close_T+1` 高于 MA5”作为早盘成交前提。
- 如使用 T+1 当日收盘信息判断是否买入，则买入时间必须改为之后可执行的交易时点；不能仍记为 T+1 早盘成交。

日线模式推荐的保守基准：
1. T 日收盘后形成候选。
2. T+1 开盘集合竞价结果和当日可交易状态确认后，模拟开盘附近可执行价格。
3. 只有开盘时可交易、未触及不可买入限制、订单规模符合参与率限制时才允许模拟成交。
4. 任何依赖 T+1 盘中走势的确认条件，均不得用于声称 T+1 开盘已成交。
5. 如策略必须等待盘中确认，转入模式 I，不得混用日线开盘成交价。

### 模式 I：盘中确认、盘中执行

- 必须有带时间戳的分钟线或更细粒度数据。
- 在时点 `τ` 作出决策时，只能读取 `bar_end_time <= τ` 且 `available_time <= τ` 的已完成数据。
- 不得使用尚未结束的当前 K 线最高价、最低价、收盘价。
- 信号确认后，订单最早在下一可执行撮合时点生效；必须设置可配置的计算延迟、下单延迟和撮合延迟。
- 若仅有 5 分钟数据，不能声称还原了 1 分钟或逐笔成交顺序。
- 盘中策略与日线策略分别训练标签、分别回测、分别报告，不得把两者结果直接拼接成同一组业绩。

## 1.3 对 R1-5 买入条件的正式替换

R1 原条件 5：

`Low_T+1 >= Close_T * (1-StopDistance)` 且 `Close_T+1 >= MA5_T+1`

**自 R2.1 起废止。**

替换为：

| 执行模式 | 可使用的买入确认条件 |
|---|---|
| 日线模式 D | 只使用开盘前已知信息、集合竞价结果、开盘可交易状态及事先定义的订单规则；不读取 T+1 全天 Low/Close |
| 盘中模式 I | 只使用决策时点前已完成的分钟 bar；确认后在下一可执行时点模拟成交 |
| 数据粒度不足 | 标记 `execution_model=UNVERIFIED`，该样本不进入严格执行绩效统计 |

`MA5` 必须使用决策时点可计算的历史数据。日线模式 T+1 早盘使用的 MA5 截止 T 日，不得使用 T+1 收盘价。

## 1.4 隔夜公告与盘中公告

公告过滤必须按 `available_time` 而不是仅按自然日日期：

- T 日收盘后至 T+1 计划下单前可用的公告，必须进入 T+1 下单过滤。
- T+1 盘中发布的公告，只能影响公告可用时间之后的决策和订单。
- 不能用 T+1 收盘后发布的公告回头取消早盘已成交订单。
- 公告发布时间精度不足或来源不可验证时，标记 `event_time_quality=LOW`，不作为精确盘中触发依据。

## 1.5 R2.1-01 验收测试

以下测试必须全部通过：

1. 将 T+1 的 High、Low、Close 改成任意数值，不得改变 T 日收盘后已生成的信号。
2. 删除 T+1 15:00 后才可用的数据，不得改变 T+1 09:30 的决策。
3. 把公告 `available_time` 从下单前移到下单后，公告不得影响之前的订单。
4. 盘中回放时，决策时点之后的 bar 不得进入特征。
5. 所有成交记录必须满足 `fill_time >= order_submit_time >= decision_time`。

# 第二章 R2.1-02：点时价格序列与公司行为账本
**修复对象：R1 方法一中“后复权只依赖过去累计因子”及“复权因子必须单调递增”的不严谨规则。**

## 2.1 废止不适用的通用假设

自 R2.1 起，废止以下通用断言：

- “所有数据供应商的后复权价都只依赖过去信息。”
- “所有复权因子都必须单调递增。”
- “只要 `close * adj_factor` 就能正确处理所有公司行为。”
- “把今天下载的复权序列转换一下，就一定能重建历史点时序列。”

复权因子的方向、基准日、修订方式和定义依赖数据供应商。不得把某一供应商字段语义当作全市场统一标准。

## 2.2 三套价格/收益对象分离

### A. 原始交易价格 `raw_price`

字段：
`raw_open, raw_high, raw_low, raw_close, raw_prev_close, limit_up, limit_down, tick_size`

用途：
- 模拟真实下单和成交；
- 判断涨跌停；
- 计算跳空；
- 判断最小报价单位；
- 记录实际价格和成交量。

**任何成交价格、涨跌停判断均使用原始交易价格及当日有效交易规则，不使用复权价。**

### B. 点时总收益序列 `pit_total_return`

用于历史收益、动量和滚动风险特征。必须按公司行为在其生效日逐日处理，且只使用当日已生效、当时可知的公司行为信息。

对相邻交易日，设：
- `P_t` 为 t 日原始收盘价；
- `P_t1` 为下一交易日原始收盘价；
- `CF_t1` 为在 t+1 生效、按每股口径换算的现金分配；
- `SF_t1` 为股本变化对应的持股数量转换系数（无股本变化时为 1）。

在数据供应商公司行为口径已经核实的前提下，单期股东总收益可按经核对的公司行为现金流与持股变化计算。实现时必须由 `corporate_action_ledger` 生成可审计的每股财富连续序列，不允许直接套用未经验证的通用 adj_factor。

若无法可靠重建现金分红、送转、配股或其他公司行为的经济效果，该证券在受影响区间的收益标签和价格类特征标记为 `CORP_ACTION_UNRESOLVED`，不得静默使用原始价格收益代替总收益。

### C. 公司行为账本 `corporate_action_ledger`

最少字段：

| 字段 | 含义 |
|---|---|
| `action_id` | 公司行为唯一标识 |
| `symbol` | 证券代码 |
| `action_type` | cash_dividend / split / bonus / rights_issue / merger / other |
| `announce_time` | 公告可用时间 |
| `record_date` | 股权登记日 |
| `ex_date` | 除权除息日 |
| `pay_date` | 现金支付日（适用时） |
| `effective_time` | 经济权益实际生效时间 |
| `cash_per_share` | 每股现金分配，明确税前/税后口径 |
| `share_factor` | 股本/持股数量变化系数 |
| `rights_terms` | 配股比例、认购价等适用条款 |
| `source_id` | 原始来源 |
| `source_revision` | 来源版本/修订号 |
| `verified_status` | VERIFIED / PENDING / REJECTED |

同一证券可能同日发生多种公司行为，不能只以 `symbol + ex_date` 作为唯一键；使用 `action_id` 或供应商事件 ID，并允许一对多。

## 2.3 点时特征生成规则

- 价格动量、波动率、均线等跨日特征，使用公司行为正确处理后的点时总收益/连续价格序列。
- 交易执行、跳空和涨跌停判断使用原始价格。
- 成交量、成交额不做价格复权；换手率必须明确分母采用当时有效流通股本。
- 历史行业分类、ST 状态、证券板块、交易制度均按有效日期回放。
- 公司行为事后更正必须保留版本；回测运行应固定 `data_snapshot_id`，不能悄悄用最新修订覆盖旧结果。
- `adj_factor` 仅作为供应商原始字段存档；只有完成定义、方向、基准日、修订行为验证后，才可用于派生序列。

## 2.4 数据主键修订

R1 中“所有表以 `symbol+trade_date` 为唯一键”废止。各表按业务实体设置主键：

| 表 | 主键建议 |
|---|---|
| `sec_master_history` | `symbol + valid_from` |
| `daily_price` | `symbol + trade_date + source_id + source_revision`；标准化后另设唯一业务键 `symbol + trade_date` |
| `intraday_bar` | `symbol + bar_start_time + interval + source_id + source_revision` |
| `index_daily` | `index_code + trade_date + source_id` |
| `industry_membership` | `symbol + industry_code + valid_from` |
| `industry_daily` | `industry_code + trade_date + source_id` |
| `corporate_action_ledger` | `action_id + source_revision` |
| `announcement` | `announcement_id + source_revision` |
| `capital_flow` | `symbol + trade_date + vendor_id + metric_version` |
| `trading_calendar_rule` | `market + rule_id + valid_from` |
| `order_event` | `order_id + event_seq` |
| `fill` | `fill_id` |
| `signal_log` | `run_id + signal_id` |

标准化行情表可以对 `symbol + trade_date` 建唯一约束，但原始供应商层必须保留来源和修订版本，不能因唯一键冲突而丢弃审计信息。

## 2.5 R2.1-02 验收测试

1. 除权除息日前后的经济总收益应与独立核算结果一致。
2. 用未来日期才发生的公司行为，不得改变此前日期已经生成的点时特征。
3. 对同一证券发生现金分红和送转等多事件，账本必须全部保留且可复算。
4. 供应商修订历史因子后，旧 `data_snapshot_id` 的结果必须可复现。
5. 涨跌停判断始终基于原始交易价格和当日有效规则。
6. 未核实的复权因子不得进入核心回测。

# 第三章 R2.1-03：订单、成交与日线路径歧义
**修复对象：R1-6 对成交价过度简化、止盈止损同日触发时路径不明的问题。**

## 3.1 区分信号、订单、成交和持仓

必须建立独立对象：

- `signal`：策略产生的交易意图。
- `order`：实际提交的订单及其价格、数量、有效期。
- `fill`：真实或模拟撮合成交。
- `position_lot`：持仓批次、可卖数量和成本。
- `exit_event`：止盈、止损、时间退出或其他退出原因。

信号不等于订单，订单不等于成交。回测不得把“满足买入条件”直接计为“已买入”。

## 3.2 成交必须遵守历史交易制度

每个交易日按证券和市场读取当日有效规则，包括但不限于：
- 涨跌幅限制及其例外；
- 最小报价单位；
- 交易时段；
- T+1 可卖数量约束；
- 停牌/复牌状态；
- 订单类型和价格限制；
- 历史交易费用规则。

不得用当前规则回放全部历史年份。规则版本缺失时，该样本标记 `RULESET_UNKNOWN`，不进入严格回测。

价格必须按当日 `tick_size` 合法取整；买卖方向的取整方式应采取不利于策略的方向，不能用四舍五入制造更有利成交价。

## 3.3 日线数据成交规则

只有 OHLC 日线时，不能知道日内先后顺序。必须使用以下规则：

### 买入

- 开盘价已处于涨停价且无可验证可成交证据：标记 `UNFILLABLE_LIMIT_UP`，不计成交。
- 停牌：标记 `SUSPENDED`，不计成交。
- 开盘价格、订单限价、涨跌停价和参与率条件均合法时，才可按预先登记的日线代理规则估算成交。
- 若无法验证开盘集合竞价可成交量或排队情况，成交状态标记 `PROXY_FILL`，并在结果中与真实成交分开报告。
- 不能因为当日最低价或收盘价后来符合条件，就回填为开盘成交。

### 卖出

- 若开盘已越过止损价，按开盘可执行价及不利滑点模拟，不得按止损价成交。
- 若日内最低价触及止损价，且最高价也触及止盈价，但没有更细粒度数据确定先后顺序：采用对持仓不利的路径，即先触发止损。
- 若仅触及止盈价，仍需验证该价格是否可成交；触及价格不等于成交。
- 若仅触及止损价，采用预先定义的止损订单成交代理，并计入滑点。
- 若开盘、最高、最低、收盘均显示一字跌停，且没有有效成交证据，不得假设卖出成功。
- 对无法确定成交与否的情形，设置 `FILL_AMBIGUOUS`，主回测按保守不利规则处理，另做敏感性区间；禁止挑选有利结果。

## 3.4 分钟线成交规则

有分钟线时：
- 只能使用已完成 bar；
- 触发价出现后，成交最早发生在下一 bar 或经验证的撮合延迟之后；
- 如果同一根分钟 bar 同时触及止盈和止损，仍无法确定路径，采用不利路径或使用更细粒度数据；
- 订单数量不能超过该时段可合理参与的成交量上限；
- 分钟线只有 OHLC、没有盘口时，仍不能声称精确复原排队优先级。

## 3.5 日线止盈止损路径示例

假设持仓成本 10.00 元，止盈 11.00 元，止损 9.50 元。某日：
`Open=10.20, High=11.20, Low=9.30, Close=10.50`

日线不能判断先到 11.00 还是先到 9.50。主回测必须按止损先触发的保守规则处理，或将该交易列为路径不确定并报告上下界。禁止按止盈先触发。

## 3.6 成交价格与成本分层

每笔交易至少输出：

- `reference_price`：信号参考价；
- `limit_price`：订单限价；
- `fill_price_raw`：原始成交价；
- `spread_cost`；
- `slippage_cost`；
- `impact_cost`；
- `commission`；
- `stamp_tax`；
- `transfer_fee`；
- `other_fee`；
- `fill_qty`；
- `fill_time`；
- `fill_quality`：REAL / MINUTE_SIM / DAILY_PROXY / AMBIGUOUS。

费用必须按交易日期、市场、证券类别和券商费率配置表计算。R1 中佣金、印花税、过户费及滑点数字只能作为待核验的研究假设，不得作为所有年份的固定费率。税费规则必须有 `valid_from/valid_to` 和来源。

## 3.7 R2.1-03 验收测试

1. 同日同时触及止盈止损，日线主回测不得选择止盈先发生。
2. 跌停无成交证据时，卖出数量必须为零。
3. 买入成交不能发生在信号或订单提交之前。
4. 成交价格必须符合当日价格笼子、涨跌停和 tick 规则。
5. 同一订单部分成交时，持仓数量只增加实际成交量。
6. `PROXY_FILL` 与真实成交分开展示，不得混成一类。

# 第四章 R2.1-04：停牌、跌停与尾部风险
**修复对象：R1-6 延迟退出和 R1-4 风险估计无法充分表达无法退出损失的问题。**

## 4.1 计划风险与实际损失分开

保留：
- 单笔计划风险预算上限 2,000 元；
- 组合计划风险预算上限 3,000 元。

新增严格定义：

- `planned_risk`：下单前按止损距离、跳空缓冲和成本缓冲估算的计划风险。
- `mark_to_market_loss`：按当前可观察价格估算的账面损失。
- `realized_loss`：实际卖出成交后确认的损失。
- `liquidation_value_estimate`：考虑可成交性和冲击成本后的估算清算价值。
- `tail_loss_scenario`：停牌、连续跌停、流动性骤降等压力情景损失。
- `risk_overrun`：实际/压力损失超过计划风险预算的金额。

禁止把 `planned_risk` 命名为 `maximum_loss` 或“最大亏损保证”。

## 4.2 延迟退出状态机

状态至少包括：

`OPEN -> EXIT_TRIGGERED -> EXIT_PENDING -> PARTIALLY_FILLED -> CLOSED`

异常分支：
- `SUSPENDED_PENDING`
- `LIMIT_DOWN_LOCKED`
- `NO_LIQUIDITY`
- `CORPORATE_ACTION_PENDING`
- `DATA_UNAVAILABLE`

规则：
1. 触发退出后持续保留退出意图，不因次日未成交而清除。
2. 每个交易日重新检查交易状态、价格限制、可卖数量和可成交量。
3. 只有实际成交数量才能减少持仓。
4. 停牌期间不得用停牌前收盘价当作可实现退出价格。
5. 连续跌停无成交时，持仓继续计入组合风险和资金占用。
6. 复牌后若有价格跳空，按复牌后可执行价格重新估算，不得沿用原止损价作为成交价。
7. 对现金分红、送转、配股等公司行为，退出数量和持仓成本必须同步调整。

## 4.3 尾部风险情景

每个持仓至少计算下列压力情景，情景幅度由历史数据与规则共同确定，不得把示例幅度当作确定性上限：

- 隔夜跳空下跌；
- 连续一个、两个及更多交易日跌停锁定；
- 停牌后复牌大幅跳空；
- 成交额骤降、参与率约束收紧；
- 同行业/同主题持仓同步下跌；
- 市场整体流动性冲击；
- 供应商数据中断或交易系统故障。

输出：
`scenario_id, scenario_loss, days_to_liquidate, liquidity_assumption, rule_assumption, confidence_level`

不得将历史 90% 分位数描述为极端损失上限。风险报告至少同时展示：
- 计划风险；
- 历史尾部估计；
- 压力情景损失；
- 已发生的风险超预算。

## 4.4 风险预算触发规则

- 新开仓前，按压力情景和计划风险两套口径检查组合。
- 若现有持仓已经处于无法退出状态，不能把其风险预算释放给新仓。
- 若组合压力损失超过预设容忍阈值，暂停新开仓；不得因风险模型输出缺失而默认风险为零。
- 风险参数缺失、价格限制规则未知或持仓状态不明时，按不允许新增风险处理。
- 不得自动强制卖出无法成交的股票；系统只能提交合规退出意图并持续监控。

## 4.5 风险输出字段

新增：
`planned_risk, mark_to_market_loss, realized_loss, liquidation_value_estimate, tail_loss_scenario, risk_overrun, locked_limit_days, suspended_days, exit_delay_days, days_to_liquidate_est, liquidity_state, risk_model_version`

## 4.6 R2.1-04 验收测试

1. 连续跌停且无成交时，持仓数量不得减少。
2. 停牌期间持仓继续占用风险预算和资金。
3. 延迟退出期间不得把原计划止损价当作实际成交价。
4. 组合中存在无法退出持仓时，不得释放其计划风险额度用于新仓。
5. 实际损失超过计划预算时，系统必须记录 `risk_overrun > 0`，不得截断损失。
6. 缺失尾部风险输入时，开仓权限应关闭而非把风险设为零。

# 第五章 R2.1-05：收益标签、预测目标与净收益口径统一
**修复对象：R1-2 标签、R1-4 Edge、R1-6 未成交样本和实际执行之间的口径断裂。**

## 5.1 训练标签必须对应可执行策略

禁止把简单的 `T 日收盘买入 -> T+h 日收盘卖出` 作为实际策略标签，除非策略本身确实能在这些时点成交。

每条候选样本应分成两层：

### 第一层：信号层（不假定成交）

记录：
- `signal_time`
- `decision_time`
- `strategy`
- `candidate_score`
- `market_state`
- `feature_snapshot_id`

### 第二层：执行层（模拟或真实成交）

记录：
- `order_submit_time`
- `fill_time`
- `fill_price`
- `fill_qty`
- `exit_order_time`
- `exit_fill_time`
- `exit_fill_price`
- `exit_reason`
- `fill_quality`

只有执行层满足成交条件的样本，才产生已实现交易收益标签。未成交候选不得伪造为零收益交易，也不得从报告中消失。

## 5.2 统一收益计算

对每笔交易按现金流账本计算净收益：

`NetPnL = ExitCashFlows - EntryCashFlows - AllFees + CorporateActionCashFlows`

收益率分母采用明确的投入资本口径：
`R_net = NetPnL / EntryCapital`

若存在分批成交、分批退出、送转、现金分红、配股或资金占用变化，应按逐笔现金流或经验证的资金加权方法计算；不能只用单一买卖价格公式覆盖所有情况。

对简单的一次买入、一次卖出且无公司行为的情形，才可使用价格比率形式作为简化校验。简化公式必须与现金流账本结果一致。

## 5.3 标签的持有期与退出规则

每个策略必须预先登记：
- 计划持有期；
- 止损规则；
- 止盈规则；
- 时间退出规则；
- 触发优先级；
- 订单类型；
- 无法成交处理；
- 成本模型版本。

标签的实际退出时间由该规则与成交模拟共同决定。若止损/止盈触发但无法成交，持仓继续延续，标签窗口也继续延长，直到真实/模拟可执行退出或样本观察窗口结束。

观察窗口结束仍无法退出时：
- 标记 `CENSORED_UNLIQUIDATED`；
- 记录最后可观察估值和压力清算估值；
- 不得把最后收盘价伪装成已实现卖出价；
- 该样本不得简单删除，应在尾部风险和未清算样本报告中单独统计。

## 5.4 预测目标分开定义

| 预测目标 | 定义 | 训练样本 |
|---|---|---|
| `P_fill` | 订单在规定有效期内成交的概率 | 所有已发出订单 |
| `P_profit_cond_fill` | 在成交条件下净收益为正的概率 | 有成交的交易样本 |
| `E_R_net_cond_fill` | 成交条件下预期净收益 | 有成交且标签完整样本 |
| `P_exit_delay` | 退出触发后发生延迟退出的概率 | 有退出意图的持仓 |
| `TailLoss` | 给定压力情景下的损失分布 | 包含延迟退出和未清算样本 |
| `E_R_net_per_signal` | 按未成交机会成本定义后的每信号期望价值 | 所有信号，须单独声明机会成本方法 |

不能将 `P_profit_cond_fill` 误称为所有信号的盈利概率。不能忽略 `P_fill` 而只报告成交后的胜率。

## 5.5 成本不得重复扣除

采用单一权威口径：

- `E_R_gross`：毛收益预测。
- `Cost_est`：预计交易成本。
- `E_R_net`：净收益预测，按毛收益与成本模型转换。
- `Edge`：若使用净收益模型，则 `Edge = E_R_net`；若使用毛收益模型，则 `Edge = E_R_gross - Cost_est`。
- 一个模型版本只能选择其中一种实现，配置字段 `edge_basis = NET | GROSS_MINUS_COST`。
- `NET` 模式下禁止再次减去成本。
- 训练标签与预测输出必须使用相同成本模型版本；实际成交复盘则使用实际费用。

## 5.6 未成交机会成本

未成交订单不应被记作已实现亏损，也不能从评估中删除。

至少报告：
- `signal_count`
- `order_count`
- `filled_order_count`
- `unfilled_order_count`
- `fill_rate`
- `missed_opportunity_return`（仅作为反事实分析，不计入真实组合收益）
- `unfilled_reason`

组合真实收益只计实际成交。策略评估另行报告每信号表现和未成交机会成本，不得混为一谈。

## 5.7 Purge / Embargo 按真实标签区间执行

R1 固定 `purge=h+1` 不再作为唯一规则。

每个样本保存：
- `label_start_time`
- `label_end_time`
- `label_status`

在训练/验证切分边界：
- 删除所有标签区间与验证区间重叠的训练样本；
- 对标签结束时间跨越边界或因延迟退出而延长的样本，按实际 `label_end_time` 清除；
- `embargo` 作为额外缓冲区，长度在训练阶段预先登记并做敏感性检验；
- 若标签未结束或未清算，按删失样本规则处理，不得假定在理论持有期结束时退出。

## 5.8 R2.1-05 验收测试

1. 同一笔交易的现金流账本与简化收益公式（适用时）必须一致。
2. 净收益模式不得二次扣费。
3. 未成交订单不能进入已实现交易胜率分母。
4. 但所有未成交订单必须进入成交率和未成交原因统计。
5. 延迟退出样本的 `label_end_time` 必须晚于原计划退出日（如实际延迟）。
6. 未清算样本必须标记删失，不得使用最后收盘价冒充成交价。
7. 训练/验证之间不存在任何标签区间重叠。

# 第六章 R2.1 统一数据字典增补

以下字段为 R2.1 最低要求，具体数据库类型由工程实现确定：

### `decision_log`

# 第七章 R2.1 回测实现顺序

按以下顺序开发，前一阶段未通过不得进入后一阶段：

1. **数据时间层**：双时间戳、历史版本、交易日历和规则版本。
2. **公司行为层**：原始价格、公司行为账本、点时总收益序列。
3. **信号层**：按决策时间生成特征和 A/B/C 信号。
4. **订单层**：信号转订单、订单有效期、T+1 可卖约束。
5. **撮合层**：日线保守代理与分钟线模拟分离。
6. **持仓层**：部分成交、可卖数量、延迟退出和公司行为调整。
7. **现金流层**：费用、分红、送转、配股及净收益核算。
8. **标签层**：成交条件标签、删失标签、按实际标签区间 Purge。
9. **风险层**：计划风险、压力损失、风险超预算。
10. **报告层**：真实成交、模拟成交、未成交、延迟退出分别披露。

# 第八章 R2.1 验收门槛与禁止事项

## 8.1 代码验收

- 所有 R2.1 单元测试通过；
- 所有时间戳使用统一时区存储，交易所本地时区用于交易规则判断；
- 每次回测固定数据快照、参数快照、规则快照和代码版本；
- 同一输入快照和代码版本能够重复得到一致结果；
- 所有成交都可追溯到订单、信号和数据快照；
- 所有实际/模拟成交清楚标记质量等级。

## 8.2 回测报告必须分开展示

1. REAL：真实成交记录（如有）。
2. MINUTE_SIM：分钟线模拟成交。
3. DAILY_PROXY：日线保守代理成交。
4. FILL_AMBIGUOUS：成交路径不确定样本。
5. UNFILLED：未成交订单。
6. DELAYED_EXIT：延迟退出样本。
7. CENSORED_UNLIQUIDATED：观察期结束仍未清算样本。

不同类别不得在不披露的情况下合并成一个“精确回测收益”。

## 8.3 禁止事项

- 禁止使用 T+1 全天 High/Low/Close 决定 T+1 早盘是否买入。
- 禁止用当前下载的全历史前复权数据直接回测历史信号。
- 禁止假设复权因子对所有供应商都单调递增。
- 禁止用复权价格判断涨跌停和真实成交。
- 禁止日线同日止盈止损双触发时选择有利路径。
- 禁止将触板等同于成交。
- 禁止将计划风险描述为最大亏损保证。
- 禁止把未成交订单计入已实现胜率或从成交率统计中删除。
- 禁止将未清算持仓按最后收盘价冒充已实现卖出。
- 禁止在净收益预测上重复扣除成本。
- 禁止用固定 `purge=h+1` 替代真实标签区间隔离。
- 禁止因模型服务或风险数据缺失而默认通过开仓检查。

# 第十章 R2.1 当前状态声明

**本补丁完成的是规则层修复，不是盈利能力证明。**

R2.1 通过规格审查后，仍需用真实历史数据验证：
- 公司行为账本是否完整；
- 交易规则历史版本是否准确；
- 日线代理成交是否足够保守；
- 分钟线撮合假设是否符合数据粒度；
- 延迟退出和尾部损失是否被完整计入；
- A/B/C 策略在扣除真实成本后是否仍有正期望。

在这些验证完成前：
- 版本状态为 `RESEARCH_ONLY`；
- 不得自动下单；
- 不得对外宣称稳定盈利；
- 不得把任何研究参数称为最优参数。

**R2.1 的完成标准：先确保回测不会使用未来信息、不会虚构成交、不会漏记无法退出的损失，再讨论策略收益。**
